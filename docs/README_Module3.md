# Модуль 3. Учёт физических ограничений (PINN)

Код: `eos/model.py` (`Thermo.all`, `physics_losses`), `eos/train.py`. Запуск:

```bash
# серия по весу условия Максвелла (дообучение из Vanilla, 50 эпох каждая)
python scripts/m2_m3_train.py --config configs/pinn_finetune_sweep.json --sweep-maxwell 0 1e-4 1e-3 1e-2 1e-1
# финальный PINN (дообучение лучшего варианта серии)
python scripts/m2_m3_train.py --config configs/pinn.json
```

## Какие ограничения и почему так

Обозначения: g_r = ∂lnP/∂lnρ, g_T = ∂lnP/∂lnT, e_r = ∂E/∂lnρ, e_T = ∂E/∂lnT = T·C_v — все получаются из
якобиана сети (эквивалент torch.autograd, модуль 2; режим `deriv="autograd"` в конфиге считает их напрямую через autograd). Все слагаемые безразмерны, поэтому одинаково работают при P ~ 10⁻³ и 10⁹ ГПа.

| Ограничение | Формула в потерях | Совместимо с данными? |
|---|---|---|
| Механическая устойчивость (∂P/∂ρ)_T > 0 | relu(ε − g_r) | да, везде |
| Термическая устойчивость C_v ≥ 0 | relu(ε − ∂y_E/∂x_T) | да (кроме скачка при 143 K) |
| Причинность c_s < c (п. 3.3) | relu(ln(c_s²/c²))², только где C_v > 0 | да; активно при T → 0 |
| c_s² > 0 | следует из двух первых | — |
| Максвелл ρ²∂E/∂ρ = P − T∂P/∂T | Huber(r_M, δ = 0.5), r_M = ρe_r/P − 1 + g_T | **нет**: в данных медиана \|r_M\| ≈ 0.3 |

Решения, принятые по ходу работы:

* **Коллокационные точки.** Физические штрафы считаются не только на train-узлах, но и на 2048 случайных точках
  на шаг, равномерных по ln ρ × ln T во всей области, — нарушения у Vanilla возникают именно между узлами.
* **Линейный hinge** для устойчивости: у Vanilla нарушения C_v < 0 многочисленны (25 % точек), но малы по величине;
  квадратичный штраф почти не даёт для них градиента.
* **Нет прямого штрафа за c_s² < 0.** При C_v → 0⁻ тепловой член c_s² ~ 1/C_v взрывается, и первая версия потерь
  разрушала обучение (ошибка P доходила до 100 %). Положительность c_s² обеспечивается условиями 1–2,
  а причинность штрафуется только там, где C_v > 0.
* **Huber для Максвелла** вместо MSE: в углу ρ → 10⁻³, T → 0.1 K давление крошечное, и |r_M| у данных доходит до 14.
* **Дообучение из Vanilla** (curriculum): сначала сеть учит форму поверхности, затем включается физика
  (линейный «разогрев» веса физики, lr 2·10⁻⁴). Это в разы дешевле обучения PINN с нуля
  (шаг PINN в ~10 раз дороже шага Vanilla из-за якобиана и коллокаций).

Веса: λ_mech = λ_therm = 1, λ_sound = 0.1, λ_Maxwell — варьируется.

## Компромисс «точность ↔ согласованность по Максвеллу»

Серия: дообучение Vanilla 50 эпох, ошибки на val (средние относительные), Huber(r_M) на коллокационных точках:

| λ_Maxwell | P | E | Huber(r_M) |
|---|---|---|---|
| 0 | 0.45 % | 0.88 % | 0.102 |
| 1e-4 | 0.44 % | 0.89 % | 0.094 |
| 1e-3 | 0.63 % | 0.98 % | 0.087 |
| 1e-2 | 3.2 % | 3.0 % | 0.062 |
| 1e-1 | 12.4 % | 12.7 % | 0.022 |

Чем сильнее навязывается Максвелл, тем дальше модель уходит от таблиц: P и E в таблицах не происходят из одной
свободной энергии (модуль 1), поэтому одновременно точно описать данные и выполнить соотношение Максвелла
невозможно. Это не недостаток PINN, а свойство данных; график — `artifacts/figures/m3_pareto_maxwell.png`.

**Выбор финальной модели:** λ_Maxwell = 1e-4 (точность как без Максвелла, невязка немного меньше), устойчивость
навязана полностью; затем ещё 100 эпох дообучения с lr 10⁻⁴ → 10⁻⁶ (`configs/pinn.json`).
Если пользователю УРС важнее согласованность (например, для энергетически консервативной схемы),
можно взять модель с λ = 1e-2 из `artifacts/models/sweep/` — все они экспортируемы тем же кодом.

## Итог (test + 200 тыс. случайных точек по всей области)

| | P, % | E, % | наруш. устойчивости, % | из них C_v<0 / ∂P/∂ρ≤0 / c_s²≤0 | медиана \|r_M\| |
|---|---|---|---|---|---|
| бейзлайн (ln P) | 0.012 | 0.027 | 1.9 | 0.19 / 0 / 0.08 (+ c_s≥c 1.7) | 0.49 |
| Vanilla | 0.22 | 0.25 | **28.4** | 25.0 / 3.6 / 2.5 | 0.48 |
| **PINN** | 0.36 | 0.59 | **0.018** | 0.016 / 0.002 / 0.015 | 0.47 |

PINN убирает нарушения устойчивости в ~1500 раз ценой ≈ 0.15–0.35 п.п. точности. Рост ошибки E сосредоточен при
T < 10³ K: монотонная по T модель не может повторить скачок E вниз при T ≈ 143 K и «размазывает» его
(см. `m2_error_heatmaps.png`) — это сознательный выбор в пользу физики.

## Дополнительные проверки (`scripts/m3_extra_physics.py`)
* **Выпуклость изоэнтроп** 𝒢 = 1 + (ρ/c_s)(∂c_s/∂ρ)_S > 0 (условие Бете–Вейля, корректность ударных волн):
  у таблиц нарушена в 2.2 % точек, у сетей — в 13–16 % (в основном при T < 10⁵ K, где C_v мала). Штраф за 𝒢 < 0
  реализован (`lam_conv`, `eos.model.fundamental_derivative`), но в эксперименте `configs/pinn_consistent.json`
  за 20 эпох ошибка выросла до 20 % / 33 % (лог `artifacts/models/pinn_convexity_attempt.log`) — открытая проблема.
* **Третье начало**: при T < 1 K |∂lnP/∂lnT| у таблиц 0, у сетей ≈ 0.02–0.03 (медиана) — выполняется приближённо.
